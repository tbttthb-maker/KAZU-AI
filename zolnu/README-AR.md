# ZOLNU 0.4.1 — iPhone

تطبيق Expo / React Native أصلي للآيفون، مع ملف IPA غير موقّع يوقّعه Sideloadly. متطلب النظام iOS 16.4 أو أحدث؛ iPad وAndroid غير مستهدفين.

## الموجود فعليًا

- منشورات نصية وصور وفيديو حتى دقيقة و25 MB، متابعة وتعليقات وإعجاب وحفظ وبحث وحظر وبلاغات.
- ملف شخصي بصورة وغلاف وإطار. علامة توثيق زرقاء مسننة بصح بيضاء بجانب الاسم وعلى الصورة، مرتبطة بقرار مراجعة من السيرفر. تغيير بيانات الهوية يوقف التوثيق لإعادة المراجعة.
- رسائل خاصة نصية مع حالة القراءة، وتفضيلات المراسلة: الجميع / المتابعون / لا أحد. الحظر يعمل في الاتجاهين لإرسال الرسائل. الرسائل محمية بصلاحيات المشاركين، وليست مشفرة من طرف لطرف.
- إشعارات داخل التطبيق محفوظة لرسائل وتعليقات وإعجابات ومتابعات جديدة. تُحدّث قائمة الرسائل/الإشعارات كل 8 ثوانٍ وهي مفتوحة. لا توجد إشعارات دفع APNs في هذا الإصدار.
- عربي وإنكليزي، و4 أنماط محفوظة: منتصف الليل والشفق والجمر والورق، ووضع تركيز وعرض مضغوط. المحتوى الذي يكتبه المستخدم لا يُترجم تلقائيًا.
- استوديو إطارات مجانية؛ لا مشتريات عملات أو دفعات تجريبية. إطار المؤسس يحتاج مكافأة الحملة. لا بث مباشر أو مجتمعات أو قصص في هذا الإصدار.
- أزيلت المنشورات والحسابات الوهمية من البداية الجديدة، وتنظّف الترقية المنشورات التجريبية المعروفة مع الحفاظ على منشورات المستخدم.
- حذف الحساب ينهي الجلسات ويحذف ملفات الوسائط وصفوف الحساب من السيرفر.

## السيرفر

مشروع Supabase الفعلي ZOLNU: `bwtgjzjgkttnfjxtrvtv` في Frankfurt. نُفذت مخططات البيانات والتوثيق والصلاحيات والرسائل والإشعارات. دالة `delete-account` منشورة. مفتاح التطبيق من نوع publishable عام، ولا يوجد secret/service-role في مصدر العميل.

تُنفَّذ الصلاحيات في Postgres RLS. وظائف المراجعة وصلاحيات الشركة في مخطط خاص مع واجهات عامة security invoker. المنشورات ووسائطها عامة للمسجلين، وملفات الوسائط المنشورة يمكن فتحها بالرابط العام. لا يوجد ادعاء أن الحساب خاص.

حساب الشركة يُمنح بعد تسجيل وتأكيد البريد `tbttthb@gmail.com` من خدمة Auth؛ لم ننشئ حساب المالك أو كلمة مروره. اللايك أثناء حملة الشركة يمنح مكافأة مؤسس دائمة منفصلة عن التوثيق الأزرق.

## ما ينتظر إعداد حسابات خارجية

مسارات الدخول مبرمجة، لكن فحص السيرفر أكد أن Google وApple وphone غير مفعلة. لا يمكن تفعيلها بمجرد وضع أزرار:

1. Google: إنشاء OAuth Web client في مشروع Google Cloud، وضبط صفحة الموافقة، ثم إضافة client ID وsecret داخل مزود Google في Supabase. Callback: `https://bwtgjzjgkttnfjxtrvtv.supabase.co/auth/v1/callback`.
2. Apple: Apple Developer Team ID وServices ID وKey ID ومفتاح Apple الخاص على السيرفر فقط؛ تسجيل callback نفسه لدى Apple. لا يوضع مفتاح Apple في التطبيق أو GitHub.
3. Supabase Auth URL Configuration: السماح بالرجوع إلى `zolnu://auth/callback`، وإضافة عنوان تطبيق مناسب كـSite URL. جلسات OAuth تستخدم PKCE وexchangeCodeForSession؛ المتصفح النظامي يعيد الجلسة إلى التطبيق.
4. الهاتف: إعداد مزود SMS مدعوم في Supabase وتفعيل phone؛ يختار المستخدم من 245 دولة/منطقة مدعومة ببيانات libphonenumber، ويُتحقق من الرقم بصيغة E.164 ثم يُرسل OTP حقيقي. إتاحة الدول لا تضمن قدرة المزود على الإرسال لكل دولة.
5. البريد: التسجيل بكلمة مرور مفعّل مع تأكيد البريد. خدمة SMTP الافتراضية محدودة بمستلمي المؤسسة وبمعدل إرسال منخفض؛ الإطلاق العام يحتاج مزود SMTP معتمدًا ودومين إرسال. لا نعطّل تأكيد البريد للتحايل على هذه الحدود.

لا تحتاج إرسال كلمات مرور أو مفاتيح خاصة في المحادثة. تُضاف أسرار المزودين داخل لوحاتهم / Supabase.

## التطوير والتحقق

```sh
npm ci
npm run typecheck
npm run lint
npm test
npx expo export --platform web
```

مجلدا ios/android مولدان ولا يُعدّلان يدويًا. توثيق SDK58 هو المرجع. البناء على macOS في GitHub Actions بالفرع `zolnu/iphone`، داخل مجلد `zolnu/`. ملف المشروع الأساسي في main لا يتغير.

أنشئ أي ترقية SQL جديدة بأمر Supabase CLI migration new، واختبرها قبل تطبيقها على المشروع. ملفات المراحل الأولى schema.sql ثم 002 ثم 003 ثم المراحل المؤرخة هي ترتيب إنشاء قاعدة جديدة. لا تعِد تشغيل المخطط الأساسي فوق المشروع الحالي.
